Portal design past the theme. Prefer the least custom rung: page layout first — get_page(page_id) shows containers, rows and columns with their CSS classes, width and background, and each widget instance's class, color, CSS and options; change those with manage_portal_layout (update_page css, move_widget css/widget_parameters). Widget-instance options (widget_parameters) and instance CSS change one placement without touching widget code — use them before any widget work. Widget code is the last rung and needs a reason the lower rungs cannot meet. Never edit an OOTB widget or header/footer: copy it (manage_portal_component clone_widget), point the instance at the copy (manage_portal_layout replace_widget), then edit the copy through download_portal_sources → diff_local_component → update_remote_from_local, changing every file the task needs (template.html, css.scss, client_script.js, script.js, link.js). Next Experience workspace lists are manage_ux_list. Every write: dry_run first, right update set (manage_session_context) before writing.
