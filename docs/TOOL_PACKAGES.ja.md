# ツールパッケージ — 高度なリファレンス

> **ほとんどのユーザーにこのページは不要です。** デフォルトのパッケージは `standard` です — 読み取り専用で、どの環境でも安全です。
> `standard` が提供する以上の書き込みツールが必要な場合のみ読み進めてください。

---

## パッケージの選択

自分の作業をカバーする最も狭いパッケージから始めてください。1 段階上がるごとに、より多くのドメインへの書き込みアクセスが追加されます:

読み取り専用 — どの環境でも安全、書き込みツールなし:

| パッケージ | ツール数 | 最大トークン | 最大（インスタンス3件） | 使うべき場面 |
| :--- | :---: | :---: | :---: | :--- |
| `core` | 12 | ~2.2K | ~2.7K | 最小限の読み取り専用: ヘルス、スキーマ、検出、キーアーティファクトの検索のみ |
| `standard` | 31 | ~7.4K | ~8.3K | **（デフォルト）** インシデント、変更、ポータル、ログ、ソース分析にわたる読み取り専用 |
| `none` | 0 | 0 | 0 | すべてのツールを意図的に無効化する（テスト、ロックダウンされた環境） |

アドオン — 汎用で、単独のパッケージではありません。どのパッケージにもカンマで追加できます（`MCP_TOOL_PACKAGE=asset_manager,scripting`）。⚠️ は書き込み可能:

| アドオン | ツール | 追加 | 用途 |
| :--- | :---: | :---: | :--- |
| `scripting` | 13 | +~4.6K | ⚠️ サーバーロジック（Script Include、Business Rule、Scheduled Job、REST Message、フロー参照）、更新セット、XML デプロイ |
| `office_files` | 2 | +~0.7K | Excel ブック（読み取り・書き込み・フォーム入力）とレコードの添付ファイル |
| `debug_window` | 3 | +~1.2K | ⚠️ 共有ブラウザ。`act_in_debug_window` は保存も押せます |
| `source_sync` | 3 | +~0.9K | ⚠️ サーバーソースのダウンロード、差分、反映 |

⚠️ 書き込み可能 — 作成/更新/削除を許可する **高度なオプション**:

| パッケージ | ツール数 | 最大トークン | 最大（インスタンス3件） | 使うべき場面 |
| :--- | :---: | :---: | :---: | :--- |
| `service_desk` | 34 | ~8.1K | ~9.1K | ⚠️ インシデントと変更の更新/クローズが必要なサービスデスクエージェント |
| `portal_developer` | 52 | ~15.8K | ~17.6K | ⚠️ ウィジェット、チェンジセット、スクリプトインクルードをデプロイするポータル開発者 |
| `platform_developer` | 45 | ~13.3K | ~14.8K | ⚠️ ワークフロー、Flow Designer、スクリプトを管理するプラットフォームエンジニア |
| `full` | 62 | ~18.2K | ~20.4K | ⚠️ 最も高度 — すべてのドメインにわたるすべての書き込みツールを一度に有効化（下記の警告を参照） |
| `asset_manager` | 7 | ~1.2K | ~1.6K | ⚠️ 資材・資産・ITOM 業務向けの最小構成：クエリと、インスタンスで事前に検証する資産の書き込み（`manage_asset`）。アドオンはカンマで追加: `scripting`, `office_files`, `debug_window`, `source_sync`（`MCP_TOOL_PACKAGE=asset_manager,office_files`） |

> **最大トークン** = リクエストごとに各パッケージのツールスキーマがモデルのコンテキストに追加する概算トークン数（tiktoken cl100k_base 基準、実際の Claude のトークン数は多少異なる）。狭いパッケージほどコンテキストとコストを節約できます。 **これは最大値**であり、通常のコストではありません。全ツールスキーマを最初に読み込むクライアントだけがこの全量を払います。ツールの遅延読み込みに対応したクライアント（例: Claude Code のツール検索）は、使うツールのスキーマだけを読み込むため、実際のリクエストあたりのコストははるかに小さくなります。 ツール数はパッケージのメンバー数です。全パッケージに `list_tool_packages` が加わり、複数インスタンス構成では `list_instances`・`compare_instances` と全ツールの `instance` パラメータが加わります — 2列目はインスタンス3件での実測値です。数値は推定ではなく tiktoken での実測です（`uv run --no-sync --with tiktoken python scripts/measure_tool_tokens.py <package>` で各ツールの内訳を表示）。

`core` と `none` を除くすべてのパッケージは、`_extends` を介して `standard` の読み取り専用ツールを継承します。完全な継承ツリーは `config/tool_packages.yaml` を参照してください。 `asset_manager` とそのアドオンは何も継承しません。セッションは要求したツールの分だけ支払います。

---

!!! danger "⚠️  `standard` より上のパッケージは、高度な書き込み可能オプションです"
    `service_desk`、`portal_developer`、`platform_developer`、`full` はすべて書き込みツールを有効化します — それらの下で動作する AI
    エージェントは ServiceNow レコードの作成、更新、削除が可能です。`full` はそれを **すべての
    ドメインで同時に**（インシデント、変更、ポータル、Flow Designer、ワークフロー、スクリプトなど）行うため、1 つの
    誤解されたプロンプトや幻覚が、複数の領域にわたる破壊的な変更を一度に引き起こす可能性があります。

    **次に該当しない限り、`standard` から上げないでください:**
    - パッケージが有効化するすべての書き込みツールを理解している（[ツールインベントリ](TOOL_INVENTORY.md) を参照）
    - **非本番** または **サンドボックス化された** インスタンスで作業している、または `allow_writes` のゲートが整っている
    - 意図しない変更からの回復方法を知っている経験豊富な ServiceNow 開発者である

    確信がない場合は、読み取り専用のデフォルト `standard` のままにし、タスクが本当に必要とするときだけ最も狭い書き込みパッケージを選んでください。

## パッケージの設定

環境変数経由（推奨）:

```bash
MCP_TOOL_PACKAGE=standard
```

CLI フラグ経由:

```bash
servicenow-mcp --tool-package standard --instance-url ...
```

MCP クライアント設定内:

```json
{
  "env": {
    "MCP_TOOL_PACKAGE": "standard"
  }
}
```

---

## ツールがパッケージに含まれていない場合に何が起きるか

現在のパッケージで有効になっていないツールを呼び出すと、サーバーは明確なエラーを返します:

```
Tool 'manage_widget' is not available in package 'standard'.
Enable package 'portal_developer' or higher to use this tool.
```

サイレントな失敗はありません — LLM は、どのパッケージを要求すべきか正確に把握します。
